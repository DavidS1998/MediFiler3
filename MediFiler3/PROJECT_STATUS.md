## Architecture and persistence

The app is a Windows 11 x64, .NET 10 C#/WPF host. App owns WPF views, dispatch, composition, WinUI hosting and monitor APIs. Application owns navigation, viewer/operation contracts and persistence services. Domain owns records. Infrastructure owns filesystem, Shell, thumbnails and SQLite adapters.

Windows App SDK 2.6.4 XAML Islands host the compact icon-only navigation rail, toolbar, Home cards, settings slider, ContentDialog controls and native media. ViewerCoordinator/ViewerHostView own cancellation, stale-result suppression and resource lifetimes. NavigationSessionState owns active folder/file/root context.

SQLite is `%LOCALAPPDATA%\MediFiler3\medi-filer.db`, **schema 7**, WAL/FULL. Separate versioned-JSON tables store ApplicationSettings, WindowLayout, RootFolderHistory and ThumbnailCacheIndex alongside immutable operation intents and append-only events. Fresh creation and migrations from versions 1-6 are supported. Schema 5 added RootScope; 6 gated replacement history semantics; 7 gated HistoryDiscarded cleanup events. State payloads remain version 1, including additive optional monitor metadata. The thumbnail service now consumes the index, with optional source-path/invalidated metadata and the approved 4.6 policy.

## Details that must survive continuation

- Settings and window layout initialize before MainWindow construction. WindowLayoutController captures on Closing before App's later Closing handler flushes settings/layout; do not move capture past dispatcher shutdown. Services write background snapshots without UI dispatch, preserve dirty state for retry, and retain corrupt/unreadable state until a real change.
- Window layout uses logical dimensions/monitor-relative offsets, but Win32 monitor rectangles are pixels. GetWindowPlacement normal bounds are workspace coordinates; convert taskbar/work-area offsets before treating them as screen coordinates. The existing WindowsWindowPlacement adapter handles this.
- WPF disallows initial maximized Show with ShowActivated=false. WindowLayoutController defers maximization to Loaded for that background-window case; ordinary app startup establishes normal bounds then maximizes on first show. Fixed panel widths remain unchanged; FolderTreeWidth in the payload is retained, not a newly adjustable control.
- The folder-tree transparency popup experiment was explicitly reverted. Keep the original WPF tree/native video clipping behavior. The settings slider's opaque matching background fix remains. Native video does not composite WPF translucency over the video surface.
- Root history/favorites must keep using BrowseView.LoadRootsAsync's explicit publication boundary. Root-history path keys and Undo root filesystem identities have different purposes; do not unify them accidentally.
- History collision Rename temporarily renames the blocking existing item, preserving recorded operation paths; the opposite history action restores it. This intentionally differs from forward-operation Rename.
- New overwrite backups use `%LOCALAPPDATA%\MediFiler3\UndoBackups` when on the destination volume; otherwise a hidden volume-root `.MediFiler3-UndoBackups-{SID hash}` folder. Files use GUID names with preserved extensions. If safe same-volume storage is unavailable, replacement fails without sibling fallback.
- Legacy `.MediFiler3-Undo-{guid}` sibling backups stay at their recorded locations and remain usable/explicitly clearable. They are not automatically migrated. Backup storage is not thumbnail cache.
- OperationMaintenanceGate serializes mutations and backup cleanup. Cleanup records HistoryDiscarded on all original operations in the owning group before deletion, retaining audit history. A locked/failed deletion may leave a backup whose dependent Undo/Redo is already retired; retry cleanup. Never delete backups by directory scan or filename pattern alone.
- ContentDialog needs a dedicated, sufficiently sized XamlRoot. WinUiContentDialogHost uses an owned borderless WPF window and ShowAsync(InPlace), preserving modality above native media and fitting the actual control height. Hide/finish the dialog before disposing its island; cancel preview work and suppress late callbacks. Do not put dialogs in the short toolbar island.

## Step 4.6 implemented policy (2026-11-10)

The user approved and implementation now includes loaded-root filesystem reconciliation and thumbnail maintenance. Schema stays 7; cache payload version stays 1 with additive optional SourcePath/Invalidated fields. No operation journal or backup lifecycle changes.

- FileSystemFolderChangeMonitor uses recursive coverage for all loaded roots while Browse is active, including inactive roots. Duplicate/nested coverage is reduced. Leaving Browse, new root loads and shutdown cancel the old session; returning starts a rescan. Refreshes with unchanged paths retain watcher coverage. Hierarchy reconciliation retains existing reparse/owned-backup exclusions and existing nodes/expansion, applying updates in batches of 32.
- FolderChangeBuffer coalesces paths case-insensitively: 500 ms quiet debounce, 2 s maximum continuous-event delay, at most 1,024 pending distinct paths. Overflow/error requests root rescans. One awaited dispatcher consumer prevents unbounded callback queues. Commands, loading, dialogs and external-opening actions defer application; context revisions/cancellation reject obsolete work. App-generated changes merge through rescanning actual current state.
- Watcher setup/health probes run off UI, with two shared probe permits, five-second healthy-root checks and failed-root exponential retries from 1 to 60 s. Failed coverage reports degraded status and polls the active folder during retries. Reconnection rescans hierarchy. A blocked Windows network call cannot be forcibly interrupted; permits bound simultaneous probes. Saved Home paths/history are never inferred or pruned.
- Reconciliation retains the selected path or nearest bounded position. Unaffected image/text/media presentation remains active. Affected media reloads paused. Automatic work never records root visits. F5 remains available and force-invalidates active-folder thumbnails, including same-length/timestamp edits. Change hints force invalidation too; unsupported/missed notifications without changed metadata still require F5.
- Existing PNG keys, three decoder workers and 32 MiB/512-entry memory LRU remain. ThumbnailCacheIndex now records owned filename/key, encoded byte size, last access and optional source mapping. Access writes batch every 30 s and flush at shutdown; failed writes retain pending state. Invalidated locked files remain marked invalid across restart and are retried rather than served as stale thumbnails. In-flight decoders cannot publish results from before invalidation/clear.
- Idle housekeeping starts after 30 s without thumbnail requests, then at most hourly. Remove entries unused for 90 days; over 1 GiB, prune least recently used toward 900 MiB. Locked/unsafe entries may keep usage above target until retry. Maintenance runs off UI, serializes passes and yields cache access between 32-entry batches. Settings displays indexed usage and offers Clear thumbnail cache. Usage can undercount legacy files until adoption.
- Only verified owned cache leaf names inside the resolved cache directory are eligible. Reject reparse directories/ancestors/leaves. Adopt valid legacy hash-named PNGs conservatively (unknown-age adoption starts at current time); unknown files remain. Legacy entries without source mapping invalidate conservatively. Recognized abandoned temporary writes older than one day can be removed. Source media, UndoBackups, saved settings/history and operation journal records are never cache-pruned. Explicit overwrite-backup cleanup and its confirmation/history-retirement rules remain separate.

Automated coverage includes debounce/overflow, duplicate/nested roots, real nested/inactive-root notifications and cancellation, tree identity/count propagation, expiry/LRU, access bookkeeping, invalidation and queued decoders, locked deletion/restart, legacy/missing/corrupt entries, temporary ownership and linked-cache rejection. Native Browse checks cover insertion/deletion, inactive hierarchy, same-metadata edits, command deferral, overflow, tab lifetime, missing nested-folder fallback, visit counts and media continuity/paused reload.
